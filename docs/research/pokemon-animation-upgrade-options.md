# Higher-quality Pokémon animation options

Research checked 2026-10-28. No runtime, model, dependency or other asset changes. No executable/add-on installed and no model archive downloaded.

**Best direction:** use full authored 3D performances, with **Pokkén Tournament DX as the strongest dramatic-motion candidate** and native Switch clips as the broader-coverage option. Start with one hero Pokémon, such as Charizard or Mewtwo, before expanding. There is no newly verified, ready-to-drop animation pack covering all 50 species.

## What the demo currently has

Local inspection covered `src/game/PokemonModel.ts`, `PokemonRig.ts`, `pokemonRigData.ts` references, the 3D manifest/provenance, existing animation audits and `scripts/prepare-remaining-species.mjs`.

- All **50 species already have GLB models**: **28 use native actions and 22 use project-authored skeletal choreography**. The latter include Arceus, Rayquaza, Giratina, Kyogre, Gardevoir, Suicune, Cinderace and Tyranitar. These are the clearest motion-upgrade targets.
- `PokemonModel.ts` loads glTF skeletal clips into Three.js `AnimationMixer`, with one mapped entrance and attack per species. `PokemonRig.ts` is a separate fallback built from single-view PNG artwork; it cannot provide unseen surfaces or full body turns.
- Main sources are [06wj/pokemon](https://github.com/06wj/pokemon) and [pokemon-party/3d-pokemon](https://github.com/pokemon-party/3d-pokemon). The latter's missing-animation cases were already identified in the local audits; “high-quality model” does not establish an attack animation.
- 06wj's current HEAD still resolves to our pinned `00d96f7f18894055e7f1db44fa0df6462e5e4c8a`. Its [151-species action manifest](https://github.com/06wj/pokemon/blob/00d96f7f18894055e7f1db44fa0df6462e5e4c8a/src/content/animatedModels.json) lists Charizard's existing `idle`, `walk`, `run`, `attack`, `happy`, `sleep` actions. Charizard already uses its 5.875-second `happy` clip for the large celebration. Redownloading that source is not an animation-quality upgrade.

## Public Pokkén files: useful, but not a complete animation package

The [Models Resource Pokkén DX catalog](https://models.spriters-resource.com/nintendo_switch/pokkentournamentdx/) has real model entries. The checked [Charizard entry](https://models.spriters-resource.com/nintendo_switch/pokkentournamentdx/asset/339139/) lists a 22.16 MB ZIP containing DAE, FBX and PNG files; [Gardevoir](https://models.spriters-resource.com/nintendo_switch/pokkentournamentdx/asset/468969/) lists 6.81 MB of DAE and PNG files. Neither file list establishes a complete native animation set. FBX/DAE can contain actions, but those binaries were not inspected. These are community distribution pages, not official licensee asset delivery.

Two concrete conversion paths exist:

- [Smash Forge's Pokkén bone-hash fix](https://github.com/jam1garner/Smash-Forge/pull/379) was merged on 2024-02-21; its author explains that the missing bone mappings prevented animation export. This resolves a documented historical obstacle, without proving every current conversion will work.
- [CrusherD2/pokken-blender](https://github.com/CrusherD2/pokken-blender) documents `.nud` models, `.vbn` skeletons, `.nut` textures and `.omo` animation import. Its own README calls it experimental and notes unsupported Wii U tiled NUT textures. It is a candidate to evaluate, not a validated dependency of this project.

## What a good integration must preserve

Use a matched rig, skin and actions, or perform deliberate offline retargeting. The current runtime has no cross-game retargeter. Rebuild `moveRigs` bone sockets and `performanceTiming` source-time mappings for each replacement; retain full recovery and calibrate VFX to the actual hands, mouth or cannons.

The current camera fits the union of idle, entrance and attack poses into a square render target. A much wider wing sweep or lunge can therefore make the Pokémon **look smaller** because the frame expands. “Bigger and more epic” needs intentional framing, actor scale and possibly camera movement as well as better clips. Current targets are 704×704 normally and 384×384 in low mode; higher texture resolution alone will be limited by that rendering path. Material conversion also replaces source shaders with toon materials, so richer Pokkén textures will need a material review.

Spine remains useful for a deliberately drawn 2D direction with separate body-part art and authored poses. A Spine license does not supply character rigs. Its [official export documentation](https://esotericsoftware.com/spine-export) supports JSON/binary skeleton data and requires the editor export version to match the runtime; a full 3D asset is not a drop-in Spine replacement.

**Suggested first comparison:** obtain a matching Charizard or Mewtwo model plus one native entrance/attack/victory action, convert only those clips, and compare it with the current model at the same screen size. Evaluate the body motion without effects first, then add restrained camera and VFX timing. This is a research recommendation; no acquisition or implementation was performed here.
